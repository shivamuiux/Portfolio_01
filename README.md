# Shivam — portfolio

A static site. No build step is needed to *publish* it: what's in this folder
is exactly what the server serves.

```
index.html                  home
work/index.html             every project on one page
projects/<slug>/index.html  one per case study
404.html                    shown for any address that doesn't exist
assets/
  shell.css  shell.js       the navbar, footer, grid, column rules, cursor,
                            logo and sound switch, and the project card —
                            shared by every page
  home.css   home.js        the home page's own sections
  work.css                  where the eight cards and the stickers sit
  project.css               the case-study layout
  media/                    images, audio, the walk sprite
.nojekyll                   tells GitHub Pages to serve the files as they are
```

Every page loads `shell.css` and `shell.js`, so the frame around the content is
written once. A visitor downloads those and `media/` on the first page and gets
them from cache on every page after — which is why a project page costs about
5 KB rather than two megabytes.

## Publishing on GitHub Pages

**Once, to set it up:**

1. Create a repository on github.com — call it `portfolio`. Leave it empty.
2. In a terminal, from inside this folder:

   ```sh
   git init
   git add .
   git commit -m "Portfolio"
   git branch -M main
   git remote add origin https://github.com/<your-username>/portfolio.git
   git push -u origin main
   ```

3. On GitHub: **Settings → Pages → Source: Deploy from a branch**, branch
   `main`, folder `/ (root)`. Save.
4. Wait a minute. The site appears at
   `https://<your-username>.github.io/portfolio/`.

**Every time after that**, publishing is three commands:

```sh
git add .
git commit -m "what changed"
git push
```

The live site updates itself within a minute.

### A domain of your own

Buy the domain, then in **Settings → Pages → Custom domain** enter it and tick
*Enforce HTTPS*. At your registrar add these DNS records:

| Type  | Name | Value |
|-------|------|-------|
| A     | @    | 185.199.108.153 |
| A     | @    | 185.199.109.153 |
| A     | @    | 185.199.110.153 |
| A     | @    | 185.199.111.153 |
| CNAME | www  | `<your-username>.github.io` |

DNS takes anywhere from minutes to a day to propagate. Once the custom domain
is live the site sits at the root, and the links keep working either way —
every path in the site is relative, so it doesn't care whether it's served from
`/portfolio/` or from `/`.

## Adding a page

The pages are generated by `build.py` in the project source. Adding a case
study is one entry in its `PAGES` list plus the writing:

```python
dict(out="projects/new-thing/index.html", body="project.body.html",
     css="project.css", title="New thing — Shivam",
     description="…", vars=dict(PROJECT="New thing", ROLE="Product design", YEAR="2026")),
```

…and one line in `CARD_LINKS` if it should appear on the home page. Then run
`python3 build.py` and commit what changes. Nothing about the shell is copied
into the new page — it inherits it.

If a page needs a layout the template doesn't cover, give it its own body file
under `src/pages/` and its own stylesheet; it still gets the navbar, footer,
grid and cursor for free.

## The contact button

`.cbtn` in the shell — one instance in the navbar, on every page. It **copies
the address**; it does not open a mail client. A `mailto:` opens nothing at all
on a machine with no mail client registered, and the wrong thing on one where
something else claimed the protocol.

Three labels are stacked on top of each other and one shows at a time —
Contact, Email on hover, Copied after a press — and the pill morphs to the
width of whichever is showing. That width is the only thing set from
JavaScript, because it is measured from the label; the rest is in the
stylesheet, driven by `data-mode` / `data-prev` / `data-press` on the button.
Every length is in `em` against its own 14px, so the shadows, the cap plate and
the specular streak rescale together instead of being blurred by a transform.

The clipboard write tries `navigator.clipboard` first and falls back to a
hidden textarea for contexts that refuse it — an insecure origin, or an older
browser. If both fail the button shows the address itself rather than claiming
a copy that did not happen. The footer's `Email:` does the same thing in place,
since there is no room down there for a pill that changes width.

## Two things worth knowing

**The display font.** The headings ask for *Exposure Trial VAR* first, which is
installed on your machine and on nobody else's — every visitor currently sees
the Newsreader fallback. To ship the real face, put the web font files in
`assets/fonts/`, add an `@font-face` rule at the top of `shell.css`, and check
the licence covers web use. (Trial licences usually don't.)

**Sound.** Browsers refuse to play audio until the visitor has interacted with
the page — a click, a tap or a keypress. Moving the mouse does not count, and
there is no setting or trick that opts out of it: the rule is enforced by the
browser, not chosen by the page, and anything that appears to dodge it is
either muted or a site the visitor has been to often enough for Chrome to
grant it autoplay.

Everything that can be done ahead of that is done. Both audio contexts — the
card hover sound's and the handwriting's — are built while the page loads and
their recordings decoded there too, which is allowed: a SUSPENDED context needs
no gesture, only resuming one does. So the first gesture has nothing to build,
nothing to decode, and only has to say `resume()`. It also answers for whatever
the pointer is already resting on, so the first sound the visitor hears is the
one they caused rather than the next one. Sound is on by default and the mute
switch lasts only as long as the visit.

## The long case studies

**FAIR**, **HostelHive** and **NIVIA** each have their own body file and
stylesheet, laid out at the Figma measurements, and their own folder of artwork: drop a WebP into
`fair/img/`, `hostelhive/img/` or `nivia/img/` named after a slot and it replaces that slot's
olive placeholder. `data-slot` in the body file is the name to use. A slot with
no file keeps its placeholder, so the page is never half-built.

HostelHive's artwork is in: the mascot and the splash screen, the three team
faces as one ringed strip, the four research photographs, both behavioural
archetype cards, the sticker, the street photograph under the problem section,
the feature matrix, and the sitemap and two user flows in the architecture
field. The final-product slot is no longer a picture at all — see below.

Two blocks are taller than the slot the design draws, because the picture in
them would otherwise be too small to read: the ecosystem map and the feature
matrix. Both are grown by a whole number of 15px rules, so everything below
them stays on the same lines the design puts it on — `vhhgrid.mjs` checks
exactly that, section by section, against the Figma frame's own remainders.

**The ecosystem map** is the prototype itself, published whole as
`assets/hh-ecosystem.html` and framed by the case study. Opened on its own it is
still the complete piece, with its heading, legend and figure caption; inside the
page it detects that it is in a frame and hides them, so the slot shows only the
map. It is always rendered at its full 1180px width and scaled down to the
column, because under 1024px the prototype drops the wheel's labels in favour of
a stacked layout.

**The final-product stage.** One conveyor, two belts, both sliding left to
right in step: fifteen wireframes underneath, fifteen finished screens above
them masked to show only on the right half, and the hand-held phone over the
seam. A screen goes behind the phone as a wireframe and comes out rendered.
Both belts carry their sequence twice and slide by exactly half their own
width, so the loop closes with no jump; every size is a fraction of the stage's
height, so it scales as one; and the belts are paused until the stage is on
screen and while the tab is hidden. The sixty image tags are written by
`fill_marquee` in build.py from whatever sits in `hostelhive/img/marquee/`, so
adding or replacing a screen is a matter of dropping a file in — `wf-*.webp`
for a wireframe, `ui-*.webp` for a finished screen. If the two lists are
different lengths the shorter one is cycled, because belts of different widths
drift out of step.

**The pictures arrive.** Each one starts masked to nothing along its own bottom
edge, 18px low and transparent, and opens upward as it comes into view —
staggered 90ms apart where several share a section. The sticker in the key
takeaways is deliberately left out. Three things to know if you touch it: the
reveal is a mask, not a `clip-path`, because an IntersectionObserver measures a
target after its clipping is applied, so a clipped picture reports an empty
intersection rectangle and could never trigger itself; the slide is
`translate`, not `transform`, because several of these pictures already carry a
centring transform; and the wipe has its own easing, because the shell's
`--ease-out` puts four fifths of the travel in the first third and the mask
crossing the picture would never be seen.

**Every colour on the page is the design's own hex**, including the marker in
the insight cards — `#1FE900`, a 10px disc centred in the 20px icon box Figma
draws it in.

## NIVIA

A brand board rather than a product case study. The rule is that what Figma
draws flat is flat here and nothing else is: the photographic boards — mockups,
billboards, apparel, packaging, posters — come across as the design's own
renders, and everything Figma draws as text, colour or vector is drawn that way
too. That means the two logo studies with their dashed construction lines, the
four lockups, the palette with its hexes, the type specimen, the scale, and the
three value cards, whose photographs are pictures but whose words are words.
The NIVIA mark is one inline path, coloured by CSS wherever it appears.

Those six boards are absolute compositions at the design's 960 width, so under
that they are scaled whole rather than reflowed — `board-fit.js` wraps each one
and reduces it, the way a printed board would be reduced.

It lives at `/projects/nivia/`. Nothing on the home page links to it — the four
cards there are the ones the home design draws, and none of them is NIVIA. The
work page is where it can be reached.

## Work

`/work/` — all eight projects, reached from the `work` link in the middle of
the navbar, which every page now carries.

The cards are the home page's component, not a copy of it: `cards.css` and
`cards.js` moved into the shell, so both pages get the same deck, the same fan
on hover, the same folder and arrow, and the same sound. Four of the eight are
the home page's own markup; the other four are that markup cloned with its
pictures and words swapped, in `make_card()`.

Touch gloves, PC Builder, Glassbeams and Service club have no `href` at all —
not a live link painted over, so there is nothing to open in a new tab and
nothing to tab to — and they carry the "coming soon" cursor. The other four open
their case study in a tab of its own (`target="_blank"`, and `rel="noopener"`
with it, so the opened page gets no handle on this one), which is set in one
place, `CARD_TARGET`, for both pages.

The five stickers below the grid, and every layer inside the four new cards,
are placed at the file's own numbers, with one correction that is worth knowing
if you ever add a card: **for a rotated layer Figma reports where its top-left
corner ended up, but a width and height that describe the box those corners now
sit inside.** Take both at face value and a layer lands as much as seventy
pixels out — PC Builder's sticker is quarter-turned, and the file says x 122
for a thing that is drawn at 51. Reading the numbers off the card frame rather
than off the layer gives the angle and the unrotated size as well, which is
what `work.css` uses.
